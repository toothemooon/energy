# V1 — MVP 最小闭环

> 目标：拍照 → AI 识别能量 → 自动保存 → 查看记录

## 成功标准

用户能完成以下完整流程，且中途无报错：

1. 点击小组件，进入拍照页面
2. 拍照或从相册选一张食物照片
3. 看到加载动画（不是空白页）
4. 看到识别结果：energyKcal（例如 642 kcal）
5. 可通过滑条微调能量值
6. 记录自动保存到 PocketBase
7. 首页显示今日记录
8. 历史记录页可查看过往记录

## 模块职责

### App 端
- 获取图片（拍照 / 相册选择）
- 压缩图片（长边 ≤ 1024px，≤ 2MB）
- 上传到 PocketBase 自定义路由
- 管理页面状态：初始 / 加载中 / 成功 / 失败
- 通过 PocketBase SDK 读写 meal_logs 记录

### PocketBase 端
- 匿名用户认证（自动创建）
- 自定义 AI 路由：接收图片、调用视觉模型、返回 energyKcal
- meal_logs Collection：存储饮食记录
- AI Key 通过环境变量保存，不暴露给客户端

### AI 视觉模型
- 识别图片中的食物
- 估算总能量（kcal）

## API 设计

### AI 识别接口（自定义路由）

```
POST /api/analyze-food
Content-Type: multipart/form-data

Fields:
  image: File（JPEG）
```

响应格式：

```json
{
  "energyKcal": 642
}
```

### 数据记录（PocketBase 普通 API）

App 拿到 AI 结果后，立即调用 PocketBase 普通 API 保存记录：

```
POST /api/collections/meal_logs/records
Headers: Authorization: Bearer <token>

{
  "user": "<current_user_id>",
  "energy_kcal": 642,
  "status": "completed"
}
```

## 数据库设计

### meal_logs Collection

| 字段 | 类型 | 说明 |
|------|------|------|
| id | text (UUID) | 主键，自动生成 |
| user | relation → users | 关联匿名用户 |
| energy_kcal | number | 能量（kcal） |
| status | text | processing / completed / error |
| created | date | 记录时间，自动填充 |
| updated | date | 更新时间，自动填充 |

## 前端状态机

```
INITIAL  →  用户点击小组件进入拍照页
    ↓
CAPTURING  →  拍照 / 选图
    ↓
COMPRESSING  →  压缩图片
    ↓
ANALYZING  →  上传到 PocketBase AI 路由
    ↓ (成功)              ↓ (失败)
COMPLETED                ERROR
保存记录到 PocketBase     提示重试
    ↓
DISPLAY  →  显示 energyKcal + 滑条
    ↓
用户调整滑条 → 调用 PocketBase Update API
```

## 分步实现计划

每一步完成后验证，再进入下一步：

| # | 步骤 | 依赖 | 验证方式 |
|---|------|------|----------|
| 1 | 拍照/选图页面 | `expo-image-picker` | 能获取图片 URI 并显示预览 |
| 2 | 图片压缩 | `expo-image-manipulator` | 压缩后图片尺寸 ≤ 1024px ✅ |
| 3 | PocketBase 假接口 | PocketBase 自定义路由 | 返回固定 JSON，App 能解析 |
| 4 | App 接入假接口 | 步骤 1-3 完成 | 走通完整 UI 流程（用假数据） |
| 5 | PocketBase 接入真实 AI | 视觉模型选型完成 | 返回真实 energyKcal |
| 6 | 错误处理与重试 | 步骤 5 完成 | 非食物图片 → 友好提示 |
