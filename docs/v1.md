# V1 — MVP 最小闭环

> 目标：拍照 → AI 识别能量 → 自动保存 → 查看记录

## 成功标准

用户能完成以下完整流程，且中途无报错：

1. 点击小组件，进入拍照页面
2. 拍照或从相册选一张食物照片
3. 看到加载动画（不是空白页）
4. 看到识别结果：energyKcal（例如 642 kcal）
5. 可通过滑条微调能量值
6. 记录自动保存到本地
7. 首页显示今日记录
8. 历史记录页可查看过往记录

## 模块职责

### App 端
- 获取图片（拍照 / 相册选择）
- 压缩图片（长边 ≤ 1024px，≤ 2MB）
- 上传到 Cloudflare Worker
- 管理页面状态：初始 / 加载中 / 成功 / 失败
- 本地 SQLite 读写饮食记录
- 匿名身份管理（Keychain）

### Cloudflare Worker 端
- 接收 multipart/form-data 图片
- 调用视觉模型（AI Key 通过 Worker Secret 保存）
- 返回简单 JSON：`{ energyKcal: 642 }`

### AI 视觉模型
- 识别图片中的食物
- 估算总能量（kcal）

## API 设计

```
POST /api/analyze-food
Content-Type: multipart/form-data

Fields:
  image: File（JPEG）
```

响应格式：

```json
{
  "energyKcal": 642
}
```

## 本地数据库设计

### meals 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT (UUID) | 主键 |
| energy_kcal | INTEGER | 能量（kcal） |
| image_uri | TEXT | 原始图片本地路径 |
| created_at | TEXT (ISO) | 记录时间 |
| status | TEXT | processing / completed / error |

### 状态说明

- `processing`: 拍照后、AI 返回前
- `completed`: AI 返回结果后
- `error`: AI 调用失败

## 前端状态机

```
INITIAL  →  用户点击小组件进入拍照页
    ↓
CAPTURING  →  拍照 / 选图
    ↓
COMPRESSING  →  压缩图片
    ↓
SAVING  →  写入 SQLite（status: processing）
    ↓
ANALYZING  →  上传到 Cloudflare Worker
    ↓ (成功)              ↓ (失败)
COMPLETED                ERROR
SQLite 更新结果          提示重试
    ↓
DISPLAY  →  显示 energyKcal + 滑条
    ↓
用户调整滑条 → 修改 SQLite 中的 energy_kcal
```

## 分步实现计划

每一步完成后验证，再进入下一步：

| # | 步骤 | 依赖 | 验证方式 |
|---|------|------|----------|
| 1 | 拍照/选图页面 | `expo-image-picker` | 能获取图片 URI 并显示预览 |
| 2 | 图片压缩 | `expo-image-manipulator` | 压缩后图片尺寸 ≤ 1024px ✅ |
| 3 | 本地 SQLite 初始化 | `expo-sqlite` | 能创建 meals 表，能插入/查询记录 |
| 4 | Cloudflare Worker 假接口 | Worker 部署 | curl 能调通，返回固定 JSON |
| 5 | App 接入 Worker 假接口 | 步骤 1-4 完成 | 走通完整 UI 流程（用假数据） |
| 6 | Worker 接入真实 AI | 视觉模型选型完成 | 返回真实 energyKcal |
| 7 | 能量调整滑条 | 步骤 6 完成 | 滑条修改后 SQLite 数据同步更新 |
| 8 | 今日首页 | SQLite 查询 | 显示今日总能量和记录列表 |
| 9 | 历史记录页 | SQLite 查询 | 可查看过往日期的记录 |
| 10 | 小组件入口 | iOS WidgetKit | 点击小组件进入拍照页 |
